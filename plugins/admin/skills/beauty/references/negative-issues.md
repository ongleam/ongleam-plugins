# 상품 목록과 원문 부정 표현

기존 `sentiment === "NEGATIVE"`인 공개 콘텐츠에 브랜드·상품 사전을 적용한다. 매칭되지 않는 글을 놓쳐도 되며 별칭 확장·유사 검색·상품 감정 재분류를 필수로 요구하지 않는다. 매칭은 언급 후보이며 상품 자체의 불만을 확정하지 않는다.

브랜드와 상품 **모두** 스킬이 원문을 읽고 부정 표현이 드러나는 연속 구간을 그대로 복사한다. 브랜드는 `negative-report.json.items[].negativeEvidence`, 상품은 `product-issues.json.items[].evidence`에 넣는다. 브랜드 근거는 해당 `body`, 상품 근거는 해당 `sourceBody`(없으면 `excerpt`)의 정확한 부분 문자열이어야 한다. 상품명 주변 excerpt 밖에 부정 표현이 있으면 같은 조회 원문의 전체 body를 `sourceBody`에 보존한다. 여러 부정 구간은 `evidenceSpans` 배열에 각각 연속 원문 그대로 저장하며 모든 구간을 표시한다. 번역·요약·문장 이어붙이기를 근거로 쓰지 않는다. 브랜드와 가까운 부정 표현을 우선하되 관계를 추정하지 않으며, 원문 전체를 확인한 뒤에도 찾지 못하면 근거를 생략한다. 글의 도입부나 상품 주변 짧은 excerpt만 보고 근거가 없다고 판단하지 않는다. 근거 누락 때문에 매칭 후보 자체를 제외하지 않는다. 렌더러는 저장된 근거를 중심으로 문맥과 `<mark>`만 표시한다.

MCP는 원문과 기존 감성 분류·사전만 조회한다. 하이라이트 생성·부정 표현 추출·Beauty 전용 분석 API를 추가하지 않는다. 조회문서·상품 모듈에도 감정 판단 규칙을 넣지 않는다.

상품 카드는 `app/product-issues.tsx`와 `data/product-issues.json`만 사용한다. 별도 `verified-product-issues.json`이나 이전 검증 사례 섹션을 만들지 않는다. 같은 플랫폼의 게시물 ID 또는 정규화 원문 URL이 같은 항목은 상품이 달라도 카드 하나로 묶고, 매칭된 상품·브랜드 이름과 모든 원문 근거를 그 카드 안에 표시한다. 원래 매칭 레코드·식별자는 보존하고 건수와 플랫폼 필터는 중복 제거된 게시물 기준으로 계산한다. 문구가 같다는 이유만으로 서로 다른 원문 게시물을 합치지 않는다. 스킬이 `lib/product-keywords.ts`의 실제 `productIssueReportSchema`를 읽어 보고서를 준비한 뒤 `bun scripts/build-product-issues.ts <보고서.json>`으로 검증·저장한다. 근거 없는 후보도 허용한다. 표본 크기·조회 완전성·원본 생성 시각은 JSON에 보존하며 화면에 세 칸 요약 숫자 영역을 다시 추가하지 않는다.

전체 소비자 갱신은 `prepare-refresh.ts`가 집계·브랜드·상품 후보를 같은 캡처로 준비하고, 스킬이 근거를 선택한 뒤 `save-refresh.ts`가 함께 저장한다. 변경 없는 원문에서 재사용하는 근거도 원문에 포함되는지 재확인한다. 기존 사례를 통합할 때 원래 조회 범위·생성 시각을 보존하고 전체 기간을 새로 조회했다고 표시하지 않는다.

소비자는 상품·브랜드 탭으로 나누고 각 탭의 부정 이슈 목록을 사용한다. 검색어 `query`, 플랫폼 배지 `platform`, 정렬 `order`와 탭 `tab=products|brands`는 URL에 보존한다. 저장된 모든 근거를 두 줄 생략으로 가리지 않는다. 저장 후 실제 상품·브랜드 카드의 근거 강조, 검색·플랫폼 배지, URL 직접 진입·새로고침·뒤로가기, 최신순·오래된순, 원문 링크를 localhost에서 확인한다. 배포 요청 시 같은 SSOT 소스 커밋의 새 Next.js 정적 빌드를 AWS에 배포하고 운영 페이지에서도 확인한다.

사전은 크롤링 transaction과 기존 원본 backfill로 자동 갱신된다. 별도 brand/product 스킬이나 수동 리뷰를 호출하지 않는다. `get_brand_keywords`, `get_brand_product_keywords`를 마지막 offset까지 읽고 상품 규칙의 `active:false`는 exact 매칭에서 제외한다. 브랜드/상품 원문 이름 전체를 검색 범위로 사용하고, 사전이 실제 운영에서 노출되는지 확인하기 전에는 전체 카탈로그 적용 완료로 보고하지 않는다.

## 보수적인 브랜드 문맥과 품질 확인

부정 리포트는 일반 단어와 같은 브랜드명의 오탐을 줄이기 위해 `brandRulesWithProductContext`로 자동 상품 사전의 활성 별칭을 브랜드 문맥으로 결합한다. 같은 문장의 브랜드명과 실제 카탈로그 상품 별칭이 함께 있어야 브랜드 후보로 표시한다. 별도 브랜드 예외 목록·감정 규칙·수동 리뷰를 추가하지 않는다. 공통 브랜드 사전은 보존하며 이 제약은 Beauty 보고서 조합에만 적용한다. 누락을 허용하는 보수적 기준이며 브랜드 단독 언급까지 전수 탐지했다고 표현하지 않는다. 상품 후보는 같은 실행의 **전체 공개 부정 원문**에 `filterNegativeProducts`를 적용한다. 이미 좁힌 브랜드 보고서만 입력하면 문장 분할 차이로 정상 상품 언급을 잃을 수 있다.

원본 전체 건수·기존 부정 건수·사전 전체/활성 규칙 수·매칭된 게시물/언급 수·화면 중복 묶음 수를 구분해 기록한다. 모든 출력 게시물의 기존 감성·공개 범위와 상품/브랜드 이름의 실제 원문을 교차 확인한다. 하이라이트는 해당 원문의 정확한 부분 문자열인지 검증한다. 이름 정규화의 반복 일치율과 수집 갱신 검증은 의미 정확도와 다르다. 사람이 정답을 붙인 표본 없이 정확도 백분율을 주장하지 않는다.
